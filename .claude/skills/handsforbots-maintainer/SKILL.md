# Hands for Bots v2 — manutenção

Monorepo pnpm (Node 20+, pnpm 10) com um kernel headless em TypeScript e um pacote por capacidade. A v1 foi removida e não há compatibilidade (ADR 0007). Arquitetura, decisões e estado do projeto: `ROADMAP.md` e `docs/adr/` (em português). Leia o ADR relevante antes de mudar um comportamento do kernel; para mudar uma decisão, escreva um ADR novo que substitua o antigo.

## Mapa

| Caminho | O que é |
|---|---|
| `packages/core/src/kernel.ts` | `H4B`: ciclo de vida, serviços, eventos, interceptadores, fila única de jobs (turnos, `runAction`, `push`), router (capture → matcher → transporte), aplicação de estímulos, persistência |
| `packages/core/src/actions.ts` | Registro e pipeline de ações: exposição por origem → `action.before` → validação → confirmação → handler |
| `packages/core/src/conversation.ts` | Histórico imutável (troca array e objetos a cada mudança) e estado compartilhado (JSON Patch) |
| `packages/core/src/types.ts`, `registry.ts` | Contratos públicos: `Signal`, `Message`, `Stimulus`, `Transport`, `Storage`; `Services`, `Events`, `Hooks` (extensíveis por declaration merging) |
| `packages/core/src/plugin.ts` | `definePlugin`, `PluginContext` (tudo registrado pelo `ctx` é desfeito no dispose), `API_VERSION` |
| `packages/transport-*` | AG-UI, Rasa, HTTP (+ `universalLLM`, `openAICompatible`), Vercel AI SDK |
| `packages/widget`, `react`, `copilotkit`, `assistant-ui` | Interfaces |
| `packages/voice`, `keyboard`, `inputs`, `menu`, `guided`, `expose-webmcp`, `mcp-apps` | Capacidades |
| `packages/voice-models`, `voice-effects` | Provedores de fala com modelos na página (Piper, Kokoro, transformers.js; fontes, download, cache) e efeitos declarativos (cadeia JSON, presets, SSML, FFmpeg). Só tipos do `voice`; runtime ONNX e fonemizador vêm do app |
| `packages/core/src/consent.ts` | `h4b.consent` (`ConsentManager`): finalidades, regras por região, canal entre abas; o kernel monta/desmonta plugins condicionados |
| `packages/memory`, `storage-local`, `storage-backend`, `tab-sync`, `consent`, `observability`, `testkit` | Infra; `consent` tem presets de regras, carregador, região e `redact`; `testkit` tem a suíte de conformidade de transportes |
| `packages/semantic-event-observability` | Biblioteca JS independente, testada com `node:test` |
| `docs/en-us`, `docs/pt-br` | Documentação pública espelhada; `references.md` guarda bibliotecas e bibliografia por tema |
| `NOTICE.md`, `docs/pt-br/NOTICE.md` | Pacotes de terceiros e código copiado (uso e licença) |
| `test/` | Verificações do repositório (`third-party.test.ts`) |
| `skills/` | Skills para quem **integra** o H4B (copiadas para `.claude/skills` do projeto consumidor) |
| `examples/react-agui`, `examples/vite`, `examples/voice-lab` | Exemplos (React + AG-UI com agente simulado; Rasa + widget via Docker; laboratório de síntese de voz com modelos reais, porta 5192) |

## Comandos

```bash
pnpm install
pnpm test                                   # Vitest em packages/*/test + node:test da semantic-event-observability
pnpm typecheck                              # tsc --noEmit em todos os pacotes
pnpm build                                  # dist/ por pacote
npx vitest run packages/<pkg>/test/x.test.ts  # um arquivo
pnpm --filter @handsforbots/example-react-agui dev
```

Rode `pnpm test` e `pnpm typecheck` antes de todo commit. O estado de base é tudo verde.

## Convenções

- TypeScript estrito (`noUncheckedIndexedAccess`, `verbatimModuleSyntax`): imports relativos com `.js`, `import type` para tipos. 2 espaços, sem ponto e vírgula, aspas simples. Comentários de código e JSDoc em inglês.
- Um pacote por capacidade. Plugins não importam outros plugins em runtime (só tipos); descobrem serviços com `ctx.get()` e reagem a `service.provided` / `service.removed`.
- Pacote novo: `package.json` com `exports` apontando para `./src/index.ts` no workspace e `publishConfig.exports` para `dist/`, `peerDependencies` em `@handsforbots/core: workspace:^`, `tsconfig.json` + `tsconfig.build.json` como os vizinhos, testes em `test/`. Registre na tabela de `packages/README.md` e em `docs/*/plugins.md`.
- **Todo comportamento tem teste.** Testes que dependem de tempo esperam condições (`eventually`, `waitForIdle`, `h4b.when`), nunca atrasos fixos. Use `jsdom` só quando precisar de DOM. Transportes novos passam pela `transportConformance` do `testkit`.
- Erros de listeners, storage e matchers vão para `emit('error', { error, source })`, nunca quebram o turno. `runAction` nunca lança.
- Segurança (ADR 0005, `docs/*/security.md`): só ações registradas executam; nada de `eval`/`window[...]`; chaves nunca no navegador; renderizadores tratam props como não confiáveis.
- **Créditos no mesmo commit.** Pacote de terceiros novo (em `package.json` ou carregado pelo hospedeiro, como `vosk-browser` e `onnxruntime-web`) ou código copiado: linha em `NOTICE.md` e `docs/pt-br/NOTICE.md` com uso e licença, conferida no `package.json` do pacote instalado e no que ele compila (ex.: o `piper-wasm` declara MIT mas traz o espeak-ng, GPL-3.0). O `test/third-party.test.ts` cobra os pacotes dos `package.json`. Bibliografia da decisão vai no `references.md` (item 4 de Documentação).
- Commits em Conventional Commits, em inglês, terminando com ponto: `feat(core): ...`, `fix(widget): ...`, `docs: ...`, `test(...)`, `chore: ...`. `feat!:` para quebra de API.

## Contratos que a documentação e as skills afirmam

Se mudar algum destes, atualize `docs/*/history.md`, `docs/*/concepts.md`, `skills/handsforbots*/` e esta lista no mesmo commit (e acrescente ou ajuste o teste):

- Turnos, `runAction` e `push` passam por **uma fila**, em ordem; `getSnapshot().queued` lista só sinais.
- Entrada com o kernel ocupado (ADR 0011): `whileBusy` (`interrupt` padrão, `merge`, `queue`; por modalidade, função ou no próprio sinal; `setInput()` em runtime) vale só para triggers `text`/`transcript`/`audio`. Turno `transport` sem saída ainda (`Current.output`) é retomado: as mensagens do turno saem do histórico e o sinal unido vai para a frente da fila; enquanto a rota é desconhecida, a entrada só enfileira e o `runTurn` a absorve se a rota for `transport` (rodando `signal.before` de novo no sinal unido). `interrupt({ by? })` marca `interrupted`, corta pelo `interrupt.before` (padrão: tudo exibido), remove a mensagem se não sobrar nada, emite `turn.interrupted` com `by` e, se cortou e `input.reportInterruptions !== false`, guarda o sinal de contexto `once` `conversation.interrupted` `{ messageId, kept, total, by }` (ADR 0015); `whileBusy: 'interrupt'` passa a modalidade do sinal como `by`; deltas que chegam depois numa mensagem interrompida são ignorados. `ask()` usa `queue`.
- Voz (ADR 0011): no `hands-free`, finais acumulam num turno pendente enviado por silêncio (`turn.silence`) ou pelo `EndOfTurn` (consultado em `minSilence`, aceito em `threshold`, `timeout` cai para silêncio, `maxSilence` é o teto); STT com `capabilities.endOfTurn` decide sozinho. As pausas contam da última mudança de parcial com texto (`pauseSince`; sem parcial, a hora do final), não da chegada do final. Estado: `pauseSince`, `endOfTurnAt` (teto) e `endOfTurnCheckAt` (só enquanto o modelo pode enviar antes; some no "não terminou" ou na falha, que move `endOfTurnAt` para `pauseSince + silence`). Barge-in chama `ctx.app.interrupt()` antes de `cancelSpeech()` (o `interrupt.before` da voz lê quantos caracteres já foram falados); backchannels por idioma não interrompem: vão ao `voice.decision` com `messageId` e `at` (caracteres falados) e, com `reactions !== false`, ao sinal `once` `voice.reactions` `{ messageId, reactions: [{ at, text }] }`, acumulado por resposta até ser enviado. Sinais `once` saem do contexto quando uma requisição ao transporte os leva (`consumeOnce`, no `runTransport`); um mais novo com a mesma chave fica; rotas sem transporte não os consomem. TTS fala frase a frase em `message.delta` (`tracks` por mensagem: `queued`/`spoken`). Filtro de eco (`echo`, padrão `textEchoFilter()`, `false` desliga, `setEcho()` em runtime): consultado em parciais e finais enquanto há frase falada há menos de `tail` ms, antes do barge-in e do turno; `''` descarta (`ignore`/`echo`); erro do filtro mantém o texto. Provedores com `consent` são pulados sem a finalidade.
- Síntese de voz (ADR 0013): provedores com `synthesize` tocam pelo `AudioPlayer` (padrão `webAudioPlayer()`) com os efeitos, e a frase seguinte é sintetizada enquanto a atual toca (`synthQueue`); falha de síntese passa a frase para o próximo provedor pronto. `load.start` (`first-use` padrão: no `setOutput` diferente de `text`, na primeira frase falada ou ao montar com `output: 'voice'`; o `listen()` não baixa, ADR 0016; `eager`, `idle`, `manual`) e `load.whileLoading` (`fallback` padrão, `wait` só espera download em andamento, `silent`); `ttsStatus` por provedor, progresso a cada 100 ms no máximo; falha de carga emite `error` com `source: 'voice:tts:<nome>'` e passa ao próximo modelo. Áudio liberado no primeiro `pointerdown`/`keydown`/`touchend` e no `listen()`. `planProsody`: o provedor aplica o que declara, o player faz altura (playbackRate compensado pelo `rate` nativo) e volume; `rate` nunca vira playbackRate. `webSpeechTTS` recebe só prosódia. `state.effects` segue o `name` dos efeitos via `subscribe`. Efeitos: formato `version: 1`, parâmetros com nomes do Web Audio (Q em dB no low/high-pass), `validateChain` lista tudo, `toFFmpeg` testado com FFmpeg real (pulado sem FFmpeg). Worker (`voice-models/src/worker.ts`): `serveTTS(provedor | fábrica(config), scope?)` no Worker e `workerTTS({ worker, config?, name?, size?, prosody? })` na página; mensagens com `tag: 'h4b:tts'` (o resto é ignorado); Worker criado no primeiro `load`/`synthesize`; `name` fixo (padrão `'worker'`), `prosody` do Worker vence a da página depois do `info`; sinais repassados por `abort`; amostras transferidas, copiadas se forem vista de buffer maior; evento `error` do Worker ou fábrica que lança → rejeita o pendente, termina, e a próxima chamada cria outro; `terminate()`. O `serveTTS` responde `ready` ao começar a ouvir; o `workerTTS` segura os pedidos até o `ready` e reenvia o `init` nele (`init` repetido é ignorado; o `info` leva `inits`). `trace(listener)` em provedores: o `voice` emite como `voice.tts` `{ provider, event }`, junto com `load.start/progress (quartos)/done/error/aborted` e `speech.while-loading`; a última falha de síntese de uma frase gera um só `error` (`voice:tts:<nome>`). A `observability` grava `voice.tts.<evento>` e `client.environment`; o export do `devPanel` leva `environment`. Skill: `skills/handsforbots-speech`.
- Atributos da conversa (ADR 0017): `setConversationAttributes` junta e `null` remove; só códigos (até 16; chave `^[a-z][a-z0-9_.-]{0,63}$`; valor número finito, booleano ou `[A-Za-z0-9_.:-]{1,64}`), o inválido sai com `error` (`conversation.attributes`); ficam em `SessionSnapshot.attributes` (limpos ao restaurar), voltam no restore e no `tab-sync`, somem no `reset()`; evento `conversation.attributes` `{ attributes, reason }` só quando mudam; salva fora de job. `expose(experiment, attributes?)` guarda em `h4b.exposures` (memória, nunca salvo; zerado no `reset()` e em restore pelo kernel) e emite `experiment.exposed`. `pickVariant` evita o anterior. Widget: opções `{ text, attributes }` → `setConversationAttributes` + `expose` antes do push; com `consent`, o índice `h4b-widget-greeting` só vai ao `localStorage` com `persistence` (antes, variável do módulo). `observability`: `obs.setAttributes` espelha a conversa; atributos em todo evento/span (`sevoAttributes`); `getTraceHeaders()` põe `baggage` (junta com o do carrier, os atributos vencem; nada com `enabled: false`); ao montar registra as exposições ainda não registradas (`late: true`) e o engajamento se já há mensagem `user`; o que foi contado fica num `WeakMap` por app (revogar e conceder não conta de novo); `h4b_experiment_exposed_total` e `h4b_conversation_engaged_total` por `recordCounter` (sem amostragem nem limite de taxa; Counter OTel criado no primeiro uso, rótulos como vieram); turno do visitante = gatilho que não é `sensor` nem `meta.reason: 'idle'`, e não conta se a conversa já tinha mensagem `user` de outro turno fora `gui-event`/`sensor`. `@handsforbots/observability/server`: `readConversationAttributes` (lista ou tipos por chave, `maxLength` 64, valores de código).
- `runAction` grava mensagem `assistant` com `toolCalls` (rota `direct` ou `agent`) + mensagem `tool` com `result` ou `error`, inclusive quando falha; persiste ao fim do job.
- Ação com `destructive: true` sem serviço `confirm` é recusada.
- Ação só com `parameters` (sem `input`) não tem os argumentos validados em runtime.
- `memory` (montado pelo `createH4B` por padrão; importa só tipos do core): conta turnos por `turnId`; `send` 20 turnos (contando o atual), `keep` 100, `compact: 'local'`; o resumo é atualizado no `request.before` e vai como sinal de contexto `memory.summary`; `keep` só remove turnos já resumidos; os transportes não cortam histórico por conta própria.
- `storageLocal`: salva após cada job, Blobs viram `omitted_media`; criptografado por padrão com a chave num cookie que expira (30 min, renovado a cada uso) ou no backend (`backendKey`); sem chave, o dado é apagado; retenção `'key'` (padrão), `{ ttlMinutes }` ou `'tab'`. Não protege contra XSS.
- `storageBackend`: GET/PUT/DELETE com `X-H4B-Conversation` e `X-H4B-Retention`; o servidor aplica a retenção.
- Serviço `retention` (ambos os storages): escolhas do desenvolvedor + `userChoices`, preferência no `localStorage`, painel 🔒 no widget.
- Consentimento (ADR 0010): sem `consent` no `createH4B`, nada é condicionado. Com ele, plugins com `definePlugin({ consent })` ou `withConsent()` só montam com a finalidade `granted` (os storages exigem `persistence`); estado = decisão > padrão da regra da região > `pending` (região assíncrona: tudo `pending` até resolver). Ao revogar: desmonta, espera o salvamento em curso, `storage.clear()` e `ctx.onRevoke`; a conversa em memória fica. `denied` apaga sobras sem montar, pelo `definePlugin({ erase(app, config) })` (ADR 0012; os dois storages implementam); o `apply` de um plugin condicionado nunca roda sem a finalidade. Decisões vão às outras abas (BroadcastChannel `h4b-consent:<channel>`). Storage montado tarde restaura só se não houver mensagem `user`.
- `storage.before` roda antes de todo salvamento (`h4b.persist()`, em série, nunca lança); o `storageBackend` envia `X-H4B-Consent` e salva de novo quando as finalidades concedidas mudam; `storageLocal.forget()` apaga conversa, preferência e chave (`KeySource.forget`).
- `tabSync`: `mode` `sync` (padrão; mesma thread → merge por id ordenado por `createdAt`; thread diferente → substitui), `notify` (`tabs.activity` + sinal de contexto `tab-sync.activity`), `off`.
- Transportes de chat enviam ações gravadas como `tool_calls` + mensagens `tool`; o `rasa` não envia histórico.
- O widget esconde mensagens sem texto/imagem/`ui`/`source` e mostra mensagens `tool` como cartões de ação (`showActions`).
- Fontes e citações (ADR 0014): `message.part` com `source` substitui a de mesmo `id` na mensagem, e partes `source` não quebram o texto (`appendText` continua a última parte de texto antes delas). `message.citations` anexa à última parte de texto; malformadas são descartadas com `error` (`source: 'message.citations'`); sem parte de texto, nada é anexado. Posições em UTF-16; `interrupt()` corta as citações além do ponto mantido. Marcadores no texto são do backend/transporte (`inlineCitations`), nunca do widget. URLs só por `safeSourceUrl` (http(s) absoluta sem credenciais ou `#âncora`; relativa nunca). Transportes não mandam fontes de volta; AG-UI `h4b.sources`/`h4b.citations` sem `messageId` vão para a última mensagem vista. Widget numera pela primeira citação; `sources.action` roda a ação com origem `user`. `sourceGroups()` agrupa o que o `sourceView` devolveu por título e página (url sem `#`); a seção é o `trail` depois do título; o cliente desenha, filtra a URL com `safeSourceUrl` e escreve o rótulo das seções.

## Documentação

Toda mudança de comportamento público atualiza no mesmo commit:

1. `docs/en-us/<página>.md` **e** `docs/pt-br/<página>.md`, com as mesmas seções e exemplos (exemplos em pt-br podem ter nomes em português).
2. Os sumários em `README.md` e `docs/pt-br/README.md` quando a página é nova.
3. `docs/*/plugins.md` para opções de pacote; `ROADMAP.md` para estado de implementação; um ADR para decisões de arquitetura.
4. `docs/*/references.md` quando a decisão se apoia em bibliotecas, serviços, artigos ou produtos de fora: link, o que é, para que serve no H4B, data de acesso, e números marcados como do fornecedor. O ADR aponta para a seção.
5. `skills/` quando muda algo que quem integra precisa saber (interrupção e voz: `skills/handsforbots-conversation`; síntese e efeitos: `skills/handsforbots-speech`). As skills só afirmam comportamentos verificados no código: confirme de novo antes de editar.

Escreva o que o código faz hoje. Exemplos de código na documentação devem compilar: quando houver dúvida, copie o trecho para um arquivo temporário em `packages/core/test/` (importando de `../src/index.js`), rode `pnpm --filter @handsforbots/core typecheck` e apague o arquivo.
